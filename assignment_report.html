1. Introduction and Pipeline

A gym management application can help staff maintain membership records and check that the API is available. A DevOps pipeline automates repeatable quality and delivery steps so changes are tested, packaged, scanned, and deployed consistently.

Project scope

This practical implements a small Flask REST API for member registration and lookup. It is a demonstration service, not a production membership platform: its sample member data is held in memory and is lost when the container restarts.

Jira → GitHub → Jenkins / GitHub Actions → pytest → Docker → Trivy → Ansible / Docker Compose

Pipeline stages

  1. Plan: break the work into trackable tasks in Jira.
  2. Version: keep the application, tests, container recipe, and pipeline definitions in GitHub.
  3. Build and test: install declared dependencies and run automated pytest checks.
  4. Package: build the application as a Docker image.
  5. Scan: check operating-system packages and declared Python dependencies for high/critical vulnerabilities.
  6. Deploy and verify: use Ansible to run Docker Compose and check the service health endpoint.

Benefits

  • Repeatable builds and automated regression checks.
  • Earlier visibility of dependency and image security issues.
  • Consistent deployment instructions across developer and CI environments.

2. Theory: Planning, Source Control and CI

1. Jira

Jira is a project and issue-tracking tool used to plan work, assign tasks, and monitor progress. For this project, suitable tasks include API implementation, testing, containerization, security scanning, and deployment automation. A real Jira board requires a signed-in account and project workspace.

2. Git and GitHub

Git records source changes as version history. GitHub hosts Git repositories and supports collaboration and pull requests. The project contains a GitHub Actions workflow definition; uploading it and obtaining a hosted Actions run requires a GitHub repository and account access.

3. Jenkins

Jenkins is an automation server that runs a pipeline defined in a Jenkinsfile. The supplied pipeline checks out source, installs dependencies, runs pytest, builds the image, scans it, and deploys with Docker Compose. A working Jenkins server and configured Linux agent are required to run it.

4. pytest

pytest is a Python test framework. Automated tests exercise the health endpoint, successful member creation, list operations, invalid input, duplicate email rejection, and unknown-member handling.

5. GitHub Actions

GitHub Actions runs workflow jobs from YAML files stored in .github/workflows. The included workflow is set to run for pushes and pull requests to main, then test, build, scan, deploy on its runner, and verify service health. A hosted run has not been claimed unless the workflow is uploaded and executed in GitHub.

3. Theory: Containers, Security and Deployment

6. Docker

Docker packages an application and its runtime dependencies as an image. A container runs that image in an isolated process environment. The Dockerfile uses a slim Python base image, installs the application dependencies, runs as a non-root user, and defines a health check.

7. Docker Compose

Docker Compose declares a service, image build, port mapping, restart policy, and health check in YAML. One command can build and run the gym API at http://localhost:8088.

8. Docker Hub

Docker Hub is a hosted container-image registry. After an interactive login, a tagged image can be pushed for sharing or deployment. No registry login, publication, or credentials are included in this local demonstration.

9. Trivy

Trivy scans container images, source dependencies, and other artifacts for known vulnerabilities. This project scans the image's operating-system packages separately from the Python packages declared in requirements.txt. This avoids treating unrelated upstream SBOM entries as installed application dependencies.

10. Ansible

Ansible automates configuration and deployment using playbooks. The supplied playbook calls Docker Compose on the local host. The playbook is configured, but Ansible was not executed on this Windows machine; its control node should run on Linux, WSL, or another supported environment.

Security note: never place registry passwords, access tokens, or other secrets in source code or screenshots. Use the CI platform's secret store for real deployments.

5. Practical Security Scan and Automation

Step 5: Test a membership request

Invoke-RestMethod -Method Post `
  -Uri 'http://localhost:8088/api/members' `
  -ContentType 'application/json' `
  -Body (@{name='Asha Patel';email='asha@example.com'} | ConvertTo-Json)

Observed result: the service accepted the example member and returned an active membership with a generated ID.

Step 6: Scan the operating-system packages

docker run --rm -v /var/run/docker.sock:/var/run/docker.sock `
  aquasec/trivy:0.75.0 image --pkg-types os --exit-code 1 `
  --severity CRITICAL,HIGH --ignore-unfixed gym-management-api:local

Observed result: no operating-system vulnerabilities were detected in the built image at scan time.

Step 7: Scan declared Python dependencies

$projectPath = (Get-Location).Path
docker run --rm -v "${projectPath}:/src" aquasec/trivy:0.75.0 fs `
  --scanners vuln --pkg-types library --exit-code 1 `
  --severity CRITICAL,HIGH --ignore-unfixed /src/requirements.txt

Observed result: no vulnerabilities were detected in the declared application dependency file at scan time.

Step 8: CI and deployment configuration

A Jenkinsfile and GitHub Actions workflow were added with test, build, security-scan, and deployment stages. A local Ansible playbook invokes Docker Compose. These configuration files are prepared; hosted Jenkins/GitHub runs, Jira board setup, Docker Hub publishing, and Ansible execution are not represented as completed because they require separate accounts or a supported host setup.
